## Описание

SPA (Single Packet Authorization): port-knocking утилита для возможности удалённого добавления себя в вайтлист файрволла сервера.

## Как работает

После установки утилиты хост закрывается от входящего трафика через nftables. Все порты и протоколы становятся недоступными. Сам сервер ни на что не отвечает, из-за чего третьи лица считают, что хост недоступен.

Далее сервер генерирует уникальный пароль, который используется для аутентификации. Сервер слушает указанный UDP-порт, но из-за концепций протокола UDP ничего на него не отвечает при неуспешных попытках, из-за чего отправитель никогда не знает открыт ли этот порт.

Клиент отправляет специальный зашифрованный UDP-пакет с паролем на заранее известный адрес и порт. Если пароль верный, сервер отвечает, а IP клиента попадает в вайтлист файрвола. При любой ошибке сервер молчит.

## Для чего нужно

Внешние системы глубокого анализа пакетов (DPI) автоматически сканируют хост в ответ на подозрительный трафик. Допустим, что ваш провайдер сливает адрес или сам ТСПУ видит подозрительную активность. Если произойдет попытка обратиться к хосту, чтобы узнать, что там хостится, то ничего не произойдет, потому что фильтруется всё, а не только популярные порты. Даже [Censys Search](https://search.censys.io/) скажет, что хост мёртв.

Утилита не является средством для обхода анализа пакетов. Это лишь инструмент для более удобного и точечного обеления IP руками с разных устройств, чтобы не заходить каждый раз на сервер из-под серийной консоли.

## Сборка и установка сервера

### Требования и зависимости

1. Ваш сервер работает на linux. Клиент может быть на любой ОС и архитектуре.
2. (опционально) У вас установлен nftables
3. (опционально) Другие файрволы не запущены. Утилита это проверяет и отключает их сама, но лучше убедиться.

### Установка

Используйте готовые скомпилированные файлы или соберите свои:

### Инициализация

После `spa-server init`:
1. Показывается предупреждение и список найденных файрволов. Вам нужно согласиться, написав 'yes'.
2. После согласия нужно указать UDP-порт от 1024 до 65535, срок хранения IP в минутах (Enter = бессрочно) и нужно ли пускать диапазоны адресов Telegram без стука (yes/no, по умолчанию no). Порт можно задать флагом `--port`, срок флагом `--retention`, Telegram флагом `--telegram`. Уже использующиеся порты, например, исходящие использоваться не будут и появится предупреждение.
3. Генерируется пароль длиной 20 символов. Его нужно сохранить.
4. Автоматически сохраняется ключ, конфиг и файлы nftables, устанавливается бинарник и systemd-юниты. Отключается ufw, firewalld, nftables.service, netfilter-persistent, iptables, docker и др., все правила сбрасываются.
   - `/etc/nftables.conf` **перезаписывается**: в нём остаётся только `flush ruleset` и `include` наших файлов. Если прежний файл был не нашим, его копия сохраняется в `/etc/spa/nftables.conf.orig`.
   - `/etc/spa/spa.nft` содержит таблицу `inet spa` (правила и список разрешённых IP), демон держит его в актуальном состоянии.
   - `/etc/spa/telegram.nft` появляется только если вы согласились пускать Telegram. Он подключается раньше `spa.nft`.
5. Порядок применения: сначала загружается наш ruleset (заменяет прежний одной атомарной операцией) и проверяется, что цепочка input действительно в режиме drop. Только после этого останавливаются и отключаются остальные файрволы, после чего наш ruleset загружается и проверяется ещё раз. Если любой шаг не удался, прежнее состояние (правила, службы, `/etc/nftables.conf`) возвращается. Копии прежних правил лежат в `/etc/spa/backup-<время>/`. Затем запускается демон.
6. При повторном `init` старый демон останавливается до записи нового ключа и пустого списка клиентов, чтобы он не мог сохранить поверх них старое состояние.

Если используется SSH, то его сессия може оборваться, а может и нет. Рассчитывать на ssh после установки не стоит, после выхода из сессии он работать уже не будет.

### Использование

```sh
spa-server init   [--port N] [--retention MINUTES] [--yes]   set up the host (as root)
spa-server serve                                             run the daemon (done by systemd)
spa-server status                                            firewall / daemon / port overview
spa-server list                                              show allowed clients
spa-server delete <number|ip>                                remove an allowed client
spa-server save                                              snapshot the live ruleset to disk
spa-server uninstall [--yes] [--keep-files]                  restore the previous firewall state and remove spa-server (as root)
```

### Удаление

```sh
sudo spa-server uninstall
```

Команда показывает, что будет восстановлено и что удалено, и просит ввести `yes`. После подтверждения:

1. Останавливается демон, отключается автозагрузка (`spa-server.service`, `spa-firewall.service`).
2. Возвращается то, что было до `spa-server init`: правила nftables и iptables, прежний `/etc/nftables.conf` (если его раньше не было, он удаляется), службы, которые `init` остановил (ufw, firewalld, docker и др.), снова включаются и запускаются.
3. Только если всё восстановилось, удаляются юниты, программа `/usr/local/bin/spa-server` (она лежит в `$PATH`) и каталог `/etc/spa` с ключом, конфигом и копиями старых правил (`--keep-files` оставляет каталог). Если что-то восстановить не удалось, ничего не удаляется, и команду можно запустить повторно.

Что нужно знать:

- Хост снова открыт настолько, насколько был открыт до установки. Если прежних правил не было, после удаления он открыт целиком. Текущая SSH-сессия может оборваться, если старые правила её не пропускают.
- Данные для восстановления `init` сохраняет в `/etc/spa/restore.json` и `/etc/spa/backup-<время>/` до первого изменения системы. При повторном `init` они не перезаписываются, чтобы исходное состояние не потерялось.
- Если хост устанавливался более ранней версией, список остановленных служб не записан: правила вернутся из копий, а службы (например, `ufw`) нужно включить самому. Команда предупредит об этом. Если не найдено вообще никаких копий, потребуется дополнительное подтверждение `open`.
- Копия `spa-server`, из которой запускали `init` (например, `./spa-server` в домашнем каталоге), не удаляется, её нужно убрать вручную.

1. [Установите Go](https://go.dev/dl/go1.27.3.windows-amd64.msi) и перезапустите терминалы

```

spa-cli.exe --host IP --port PORT
```

### Если не хочется вводить пароль каждый раз руками, можно передавать через пайплайн `--password-stdin`:

#### Linux
```
echo PASSWORD | ./spa-cli --host IP --port PORT --password-stdin
```

#### Windows
Пробела между паролем и `|` быть не должно:
```
echo PASSWORD| spa-cli.exe --host IP --port PORT --password-stdin
```

Подробнее:
```
spa-cli
  --host SERVER         # IP сервера
  --port PORT           # Порт
  [--timeout 30s]       # Ручное указание таймаута, после которого попытки аутентифицироваться прекращаются
  [--password-stdin]    # Для ввода пароля из cli-пайплайна
```

## Что стоит знать

- Повтор перехваченного HELLO с верным паролем получит от сервера CHALLENGE, зашифрованный ключом, которого у атакующего нет: использовать его нельзя. Но это единственный случай, когда сервер отвечает тому, кто пароля не знает (за исключением того, что вы разрешили доступ к CIDR Телеграма для технических целей). Сервер помнит токен 2 минуты, после этого повтор снова получает ответ.
- Потеря пароля: повторный `spa-server init` создаёт новый. Старый перестаёт работать, список клиентов очищается.
- IPv6 полностью закрыт. В том числе из-за этого не работает NDP, и IPv6-связность хоста отключена.
- Срок после перезагрузки считается от последнего снимка: не более минуты расхождения плюс время простоя.
- Docker/контейнеры отключаются при установке.
- Порт из диапазона исходящих соединений (по умолчанию это 32768-60999) работает, но в редких случаях может быть
  занят исходящим соединением при загрузке до старта демона. Утилита предупреждает об этом.
- Обновление со старой версии (где всё лежало в `/etc/spa/nftables.conf`): нужен повторный `spa-server init`, он перенесёт загрузку на `/etc/nftables.conf` и `/etc/spa/spa.nft`. Пароль при этом меняется.
